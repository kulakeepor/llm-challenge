# 阈值校准记录

每次在真实算力上用参考实现跑模板，都记在这里。参考实现本身不公开。

## 阶段一 · Colab T4 · 2026-11-27

| 项 | 值 |
|---|---|
| 算力 | Colab 免费 T4（`cuda:Tesla T4`），torch 2.14.1+cu130 |
| 语料 | chinese-poetry《全唐诗》58 个文件（MIT），3,725,688 字，9,589 种字；前 90% 训练，后 10% 验证 |
| 分词器 | BPE，字种数 + 2000 次合并（词表 11,411），每 token 约 1.11 字；训练 + 编码 4.1 分钟（不计入训练耗时） |
| 模型 | 模板默认：6 层、6 头、384 维、上下文 128，1935 万参数 |
| 训练 | AdamW，lr 3e-4，batch 64，3000 步 |
| 结果 | **17.8 分钟，验证 bpc 7.26**；形状、因果性（0.0）、KV Cache 一致全部通过 |

bpc 随训练步数的变化：

| 步数 | 250 | 500 | 1000 | 1500 | 2000 | 2500 | 3000 |
|---|---|---|---|---|---|---|---|
| 分钟 | 1.3 | 2.8 | 5.8 | 8.8 | 11.8 | 14.8 | 17.8 |
| bpc | 9.23 | 8.89 | 8.18 | 7.76 | 7.51 | 7.35 | 7.26 |

成绩单交给网页判定：除 bpc（7.26 > 7.0）外全部通过，失败原因显示正确。

### 发现
1. 模板默认 `VOCAB_SIZE = 2000` 小于中文语料的字种数（9,589），BPE 无法开始合并。已改为“字种数 + 2000”。
2. 验证集有 0.06% 的字在训练集里没出现过，分词器必须能处理未见过的字。已在模板里提示。
3. 默认 3000 步达不到 bpc ≤ 7.0；在 120 分钟预算内训练更久大概率可以，但还没实测。
4. **bpc 和语料强相关**：古诗每个字信息量大，bpc 天然偏高；换成现代白话文，同样的模型 bpc 会低很多。只要学员能自选语料，固定的 bpc 阈值就不公平。待决定：指定统一语料，或者把阈值改成相对基线的值。
